# Nowa Music 公式サイト 設計書

作成日: 2026-08-11
公開URL: https://nowajp.com

## 1. 目的

Nowa Music というアーティストの**世界観を見せる**こと。
楽曲カタログでも問い合わせ窓口でもなく、「夜にそっと寄り添う女性ボーカルJ-POPバラード」という空気を、来た人が数秒で感じ取れる場所にする。

副次的な役割として、YouTube・サブスク・SNSへの導線を1箇所にまとめる。

### 成功の基準

- スマホでトップを開いた瞬間に「夜」「静けさ」が伝わる
- 迷わずに1曲目を再生できる（再生開始までのクリックが1回）
- 新曲やアルバムを追加しても、サイト側の手作業が発生しない

## 2. 前提条件

| 項目 | 内容 |
|---|---|
| チャンネル | https://www.youtube.com/@nowa_music_jp |
| コンテンツ | オリジナル単曲100曲以上、1時間のアルバム（長尺動画・再生リストの両方） |
| Nowa の見せ方 | キャラクター／アバター（キャラクターシートのストックあり） |
| 配信先 | YouTube、Spotify・Apple Music などサブスク、TikTok、Instagram |
| 言語 | 日本語のみ |
| ドメイン | nowajp.com（Squarespaceで取得済み・有効期限 2026/10/04） |
| ホスティング | GitHub Pages（無料）。GitHubアカウントは取得済み |

## 3. サイト構成

ページは3つ。情報を増やさず、世界観に集中させる。

### 3.1 トップ `/`

縦スクロールで読ませる一本道。上から順に:

1. **ヒーロー** — 全画面のNowaのビジュアル。キャッチコピー1行と `▶ 今夜の1曲` ボタンのみ
2. **世界観** — チャンネル説明の文章を、スクロールに合わせて静かに浮かび上がらせる
3. **アルバム棚** — アルバムを大きなカードで並べる（本サイトの主役）。トップには最大8件まで、それ以上は `/music` へ送る
4. **新着曲** — 最新6曲
5. **Nowaについて** — 抜粋とABOUTページへの導線
6. **聴けるところ** — YouTube / Spotify / Apple Music / TikTok / Instagram

### 3.2 ミュージック `/music`

1ページに「アルバム全部」と「最新20曲」をまとめる。
20曲より前の曲は載せず、末尾に「もっと聴く → YouTubeチャンネル」を置く。

### 3.3 アバウト `/about`

キャラクタービジュアルを大きく使ったプロフィール。誰に向けた、どんな夜のための音楽かを語る。

### 3.4 共通

- ヘッダー: ロゴ ＋ `MUSIC` `ABOUT` のみ
- フッター: SNSリンク、メールアドレス、コピーライト
- 問い合わせフォームは作らない（フッターのメールリンクで足りる）

## 4. ビジュアル

方向性: **月光**（深い藍 × 明朝体）

| 要素 | 指定 |
|---|---|
| 背景 | `#070d1c` → `#101d3c` のグラデーション。月明かりのような淡い光を一点 |
| 文字色 | `#e8edf7` |
| アクセント | `#9db4e0`（ボタン、区切り線に少量） |
| 書体 | 明朝体（Noto Serif JP）。見出しは細く、行間を広く |
| 写真 | キャラクター画像は暗く落として背景に馴染ませ、輪郭だけ光らせる |
| 動き | スクロールで文字がゆっくり浮かび上がる程度。派手なアニメーションはなし |
| 優先 | スマホ優先（YouTube概要欄からの流入はほぼスマホのため） |

## 5. データの仕組み

### 5.1 取得するもの

| 種類 | 定義 | 表示 |
|---|---|---|
| アルバム | 20分以上の長尺動画、および公開再生リスト | アルバム棚に大きなカードで。再生リストは収録曲も展開できる |
| 楽曲 | 20分未満の動画のうち、新しい順に20件 | 新着曲セクション（6件）とMUSICページ（20件） |

サムネイルはYouTubeのものをそのまま使う。

### 5.2 更新の流れ

1. GitHub Actions が毎朝1回（および手動実行時）起動
2. YouTube Data API v3 でチャンネルの動画一覧と再生リストを取得
3. `data/youtube.json` を生成
4. サイトをビルドし GitHub Pages へ公開

新曲をYouTubeにアップすれば、翌朝には自動でサイトに反映される。

### 5.3 決めごと

- **APIキー** は GitHub の Secrets に保管する。ビルド時にのみ使い、公開されるコードには含めない
- **取得に失敗した日** は前回の `data/youtube.json` をそのまま使い、ビルドを継続する。サイトが空になることはない
- **サブスクリンクは曲ごとに持たない**。サイト全体で1箇所（「聴けるところ」とフッター）にアーティストページへのリンクを置く。100曲分のURLを手で集めるのは現実的でないため
- **再生** は、曲をクリックするとサイト内でYouTubeプレイヤーが開く方式。外部に飛ばさない。プレイヤー内にチャンネル登録ボタンが表示される

## 6. 技術構成

- **Astro** による静的サイト生成
- **GitHub Pages** で公開、**GitHub Actions** でビルドと日次更新
- 外部サービスへの課金は発生しない（ドメイン更新料を除く）

### 構成要素

| 単位 | 役割 | 依存 |
|---|---|---|
| 取得スクリプト | YouTube API を叩き `data/youtube.json` を書く | APIキー（Secrets） |
| データ層 | JSON を読み、アルバム／楽曲に整形して各ページへ渡す | `data/youtube.json` |
| ページ（3つ） | 受け取ったデータを表示する | データ層 |
| プレイヤー | クリックされた動画IDでモーダルを開く | なし（独立） |

取得スクリプトはサイト本体から切り離す。APIが変わってもページ側を触らずに済ませるため。

### エラー時の扱い

| 状況 | 挙動 |
|---|---|
| API が失敗 / 制限超過 | 前回のJSONでビルドを継続し、Actions のログに警告を残す |
| 動画が非公開になった | 翌朝の取得で自然に消える |
| サムネイルが読めない | 背景色のプレースホルダーを表示し、レイアウトは崩さない |

## 7. ドメイン接続（nowajp.com）

Squarespaceのドメイン設定 → DNS で以下を追加する。Squarespace側でサイトを作る必要はない。

- `@` に Aレコード4件: `185.199.108.153` / `185.199.109.153` / `185.199.110.153` / `185.199.111.153`
- `www` に CNAME: `<GitHubユーザー名>.github.io`

GitHubリポジトリの Settings → Pages でカスタムドメインに `nowajp.com` を設定し、**Enforce HTTPS** を有効にする。証明書は自動発行される。
`www.nowajp.com` は `nowajp.com` に統一する。

## 8. 検証

- 取得スクリプト: API応答のサンプルを使い、アルバムと楽曲の振り分け（20分の境界）、失敗時に前回JSONを維持することを確認する
- 表示: iPhone相当の幅とデスクトップ幅で、3ページとも崩れないことを確認する
- 公開後: `https://nowajp.com` と `https://www.nowajp.com` の両方がHTTPSで開くことを確認する

## 10. 実装前に必要なもの

制作を始める前に、以下を用意する。

| 必要なもの | 用途 |
|---|---|
| YouTube Data API キー | 動画とアルバムの自動取得（Google Cloudで無料取得。手順は実装計画に含める） |
| GitHubのユーザー名 | DNSのCNAME設定と、リポジトリ作成 |
| キャラクター画像 | ヒーローとABOUTページ。縦長1枚（ヒーロー用）と、その他数枚 |
| キャッチコピー1行 | ヒーローの文言。案は制作側から複数出し、選んでもらう |
| 公開用メールアドレス | フッターのリンク先 |
| SNSアカウントのURL | Spotify / Apple Music / TikTok / Instagram のアーティストページ |
