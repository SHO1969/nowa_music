# Nowa Music サイト 運用メモ

## 新曲・新アルバムを出したとき

何もしなくてよい。毎朝6時（日本時間）にYouTubeから自動で取り込まれ、サイトが更新される。

## すぐ反映したいとき

GitHubのリポジトリ → Actions → 「更新と公開」→ 「Run workflow」を押す。3分ほどで反映される。

## 変えたくなったときの場所

| 変えたいもの | ファイル |
|---|---|
| SNS・サブスクのリンク、メールアドレス | `src/lib/links.js` |
| トップのキャッチコピー | `src/pages/index.astro` |
| ABOUTの文章 | `src/pages/about.astro` |
| 配色・書体 | `src/styles/theme.css` |
| アルバムの判定時間（既定20分） | `src/lib/catalog.js` の `ALBUM_MIN_SECONDS` |
| 表示する楽曲数（既定20曲） | `src/lib/catalog.js` の `trackLimit` |

## サイトが更新されなくなったら

1. Actions のログを見る。「YouTubeの取得に失敗しました」と出ていたらAPIの問題
2. よくある原因: APIの1日の上限（無料枠1万ユニット）超過 → 翌日に自動復旧する
3. Google Cloud のプロジェクトが無効化されていないか確認する
4. 取得に失敗しても、サイトは前回のデータで表示され続ける（真っ白にはならない）

## サイトが「空」になった／Actionsが赤くなったら

上の4は「前回のデータが残っている場合」の話。次のケースだけは例外で、**Actionsが失敗（赤色）扱いになる**ようにしてある。目印はActionsのログに出る `::error::` の行。

1. **Secrets（YOUTUBE_API_KEY / YOUTUBE_CHANNEL_ID）が未登録・打ち間違い・失効している場合**
   とくに一番最初の公開や、APIキーを作り直した直後に起きやすい。GitHubのリポジトリ → Settings → Secrets and variables → Actions で、2つのSecretsが正しく登録されているか確認する。値を直接見ることはできないので、疑わしければ作り直して登録し直すのが早い。
2. **Google CloudでAPIキーを作り直したとき**
   APIキーには「YouTube Data API v3のみ使える」という制限をかけてある（セキュリティのため）。キーを作り直した場合は、この制限を入れ忘れると動かない、または悪用のリスクがあるので、必ず同じ制限を設定し直すこと。
3. **将来 main ブランチに保護設定（ブランチ保護）をかけた場合**
   自動更新の仕組みは、GitHub Actionsが直接 `main` に `git push` することでYouTubeのデータをコミットしている。ブランチ保護（レビュー必須など）を設定すると、このpushが弾かれてその日の自動更新が止まる。ブランチ保護を入れる予定があれば、Actionsのpushだけは例外にする設定（bypass）が必要になる。

## ドメイン
